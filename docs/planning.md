# Bplogger 기획 정리본

## 1. 기획 요약

Bplogger는 하루 건강 기록을 날짜 단위로 관리하는 Android 앱이다.
핵심은 `아침 혈압`, `저녁 혈압`, `체중`, `메모`를 각각 다루면서도 월별 캘린더에서 하루 상태를 빠르게 파악할 수 있게 하는 것이다.

제품 중심은 아래 두 축이다.

- 날짜별 기록 추가 및 수정
- 캘린더와 그래프를 통한 기록 탐색

## 2. 핵심 가치

- 빠른 확인: 월별 캘린더에서 아침/저녁 기록 상태를 즉시 확인
- 빠른 저장: 선택한 날짜에 혈압과 체중을 추가 또는 수정
- 기록 관리: 과거 데이터 조회 및 수정
- 해석 지원: 최근 기준 그래프로 변화 확인
- 누락 방지: 사용자 설정 기반 아침/저녁 알림 제공

## 3. 제품 범위

### 3.1 포함 범위

- 아침 혈압 저장
- 저녁 혈압 저장
- 체중 저장
- 날짜별 신규 추가 및 수정
- 날짜 메모 추가/수정/삭제
- 월별 캘린더 화면
- 일별 상세 화면
- 그래프 탭 화면
- 사용자 설정 기반 알림
- 로컬 DB 저장

### 3.2 제외 범위

- 회원가입 / 로그인
- 서버 저장 / 동기화
- 운영체제 캘린더 연동
- 공유 기능
- 다기기 동기화

## 4. 주요 사용자 시나리오

### 시나리오 A. 오늘 아침 기록 저장

1. 사용자가 앱을 실행한다.
2. 앱은 월별 캘린더와 오늘 상태를 보여준다.
3. 사용자는 오늘 날짜 입력 영역에서 아침 혈압을 입력한다.
4. 저장 후 오늘 날짜는 `아침만 기록됨` 상태로 갱신된다.

### 시나리오 B. 오늘 저녁 기록 보완

1. 사용자는 같은 날짜에 다시 앱을 연다.
2. 저녁 혈압을 입력한다.
3. 저장 후 오늘 날짜는 `아침/저녁 모두 기록됨` 상태로 바뀐다.

### 시나리오 C. 기록이 없는 날짜에 신규 추가

1. 사용자가 캘린더에서 기록이 없는 날짜를 선택한다.
2. 앱은 해당 날짜에 추가 가능한 입력 UI를 보여준다.
3. 사용자가 혈압 또는 체중을 입력해 저장한다.
4. 저장 후 해당 날짜 상태와 그래프가 갱신된다.

### 시나리오 D. 과거 기록 수정

1. 사용자가 캘린더에서 기록이 있는 날짜를 선택한다.
2. 앱은 일별 상세 화면으로 이동한다.
3. 저장된 혈압 또는 체중을 수정한다.
4. 캘린더 상태와 그래프가 함께 갱신된다.

### 시나리오 E. 메모 관리

1. 사용자가 특정 날짜 상세 화면에서 메모를 입력한다.
2. 메모는 과거/오늘/미래 날짜와 무관하게 저장할 수 있다.
3. 사용자는 이후 다시 열어 수정하거나 삭제할 수 있다.

### 시나리오 F. 그래프 확인

1. 사용자가 그래프 탭으로 이동한다.
2. 기본값으로 최근 7일 그래프를 본다.
3. 필요하면 최근 30일로 전환한다.
4. 혈압 2라인 그래프와 체중 그래프를 같은 화면에서 확인한다.

## 5. 화면 구조

- 메인 화면
  - 캘린더 탭
  - 그래프 탭
- 일별 상세 화면
- 알림 설정 화면

## 6. 캘린더 탭 기획 포인트

- 월별 캘린더가 첫 화면이어야 한다.
- 날짜별 상태는 4단계로 보여야 한다.
  - 기록 없음
  - 아침만 기록
  - 저녁만 기록
  - 아침/저녁 모두 기록
- 상태 표시는 중립색/아침 강조색/저녁 강조색/완료색 규칙을 기본으로 한다.
- 색상 외에도 텍스트 또는 접근성 라벨을 제공해야 한다.
- 하단 입력 영역은 선택 날짜 기준 추가 또는 수정 흐름을 제공해야 한다.
- 기록이 없는 날짜는 추가, 기록이 있는 날짜는 수정 중심 흐름을 제공해야 한다.

## 7. 상세 화면 기획 포인트

- 선택 날짜의 아침 혈압, 저녁 혈압, 체중, 메모를 한 화면에서 보여준다.
- 저장된 혈압과 체중은 수정/삭제할 수 있어야 한다.
- 메모는 별도로 수정/삭제할 수 있어야 한다.
- 혈압과 체중을 수정해도 기존 측정 시간은 유지해야 한다.

## 8. 그래프 기획 포인트

- 기본 기간은 최근 7일이다.
- 기간 전환은 최근 7일/최근 30일을 지원한다.
- 혈압은 수축기/이완기 2라인으로 보여준다.
- 체중은 분리된 그래프로 보여주되 같은 화면에 함께 배치한다.

## 9. 구현 우선순위

### Phase 1. 데이터 구조 전환

- 날짜 단위 건강 기록 모델 정의
- 아침/저녁/체중 저장 필드 및 시간 필드 정의
- 날짜 메모 모델 정의
- 알림 설정 모델 정의
- 수정 시 측정 시간 유지 정책 반영

### Phase 2. 캘린더 중심 탐색 구축

- 월별 캘린더
- 날짜 선택
- 일별 상세
- 날짜 상태 계산

### Phase 3. 입력/수정 흐름 구축

- 기록 없는 날짜 신규 추가
- 기록 있는 날짜 수정
- 메모 편집
- 검증 메시지

### Phase 4. 그래프 및 알림

- 최근 7일/최근 30일 그래프
- 알림 설정 화면
- 아침/저녁 미기록 판정
- 스케줄링 안정화

## 10. 기획상 주의점

- 혈압/체중은 기록이 없는 날짜에는 추가, 기존 기록이 있는 날짜에는 수정이라는 정책을 UI에서 명확히 드러내야 한다.
- 메모는 미래 날짜에도 가능하므로 입력 정책이 혈압/체중과 다르다는 점을 혼동 없이 보여줘야 한다.
- 캘린더 상태 표시 규칙은 색상만으로 끝내지 말고 접근성도 고려해야 한다.
