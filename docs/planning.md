# Bplogger 기획 정리본

## 1. 기획 요약

Bplogger는 하루 건강 기록을 날짜 단위로 관리하는 Android 앱이다.
현재 제품 중심은 `빠른 입력`과 `간단한 확인`이다.

핵심 축은 아래 두 가지다.

- 첫 화면에서 선택 날짜 기준으로 빠르게 입력
- 컴팩트한 캘린더와 그래프로 기록 확인

## 2. 핵심 가치

- 빠른 저장: 앱 첫 진입 시 오늘 날짜를 기본 선택하고 바로 기록 입력
- 빠른 전환: 날짜를 바꾸면 즉시 해당 날짜 입력 대상으로 전환
- 빠른 확인: 컴팩트한 월별 캘린더에서 상태 확인
- 선택적 관리: 더 깊은 수정/삭제/메모는 상세 화면에서 수행

## 3. 주요 사용자 시나리오

### 시나리오 A. 앱 첫 진입 후 오늘 기록 저장

1. 사용자가 앱을 실행한다.
2. 앱은 오늘 날짜를 기본 선택한 상태로 메인 화면을 보여준다.
3. 사용자는 메인 입력 카드에서 아침 혈압이나 저녁 혈압, 체중을 입력한다.
4. 저장 후 오늘 날짜 상태가 즉시 갱신된다.

### 시나리오 B. 다른 날짜 선택 후 바로 입력

1. 사용자가 캘린더에서 다른 날짜를 선택한다.
2. 앱은 메인 입력 카드의 대상을 해당 날짜로 바꾼다.
3. 사용자는 같은 화면에서 바로 입력 또는 수정을 진행한다.

### 시나리오 C. 세부 관리

1. 사용자가 선택 날짜의 더 자세한 수정이나 메모 관리가 필요하다.
2. 상세 화면으로 진입한다.
3. 상세 화면에서 삭제, 메모, 세부 관리 작업을 수행한다.

## 4. 화면 구조

- 메인 화면
  - 캘린더 탭
  - 그래프 탭
- 일별 상세 화면
- 알림 설정 화면

## 5. 메인 화면 기획 포인트

- 첫 진입 시 오늘 날짜가 기본 선택되어야 한다.
- 메인 화면은 입력 우선 구조여야 한다.
- 캘린더는 확인 중심의 컴팩트한 월력 UI여야 한다.
- 날짜 셀 탭의 기본 동작은 상세 이동이 아니라 입력 대상 날짜 변경이어야 한다.
- 상세 화면은 선택적으로 진입하는 관리 흐름이어야 한다.

## 6. 캘린더 기획 포인트

- 날짜별 상태는 4단계로 보여야 한다.
  - 기록 없음
  - 아침만 기록
  - 저녁만 기록
  - 아침/저녁 모두 기록
- 상태는 중립색/아침 강조색/저녁 강조색/완료색 규칙을 기본으로 한다.
- 색상 외에도 텍스트 또는 접근성 라벨을 제공해야 한다.
- 버튼을 나열한 느낌보다 익숙한 월력 구조를 우선한다.

## 7. 상세 화면 기획 포인트

- 상세 화면은 주 입력 화면이 아니라 세부 관리 화면이다.
- 선택 날짜의 혈압, 체중, 메모를 확인하고 관리한다.
- 혈압과 체중을 수정해도 기존 측정 시간은 유지해야 한다.

## 8. 그래프 기획 포인트

- 기본 기간은 최근 7일이다.
- 기간 전환은 최근 7일/최근 30일을 지원한다.
- 혈압은 수축기/이완기 2라인으로 보여준다.
- 체중은 분리된 그래프로 보여주되 같은 화면에 함께 배치한다.

## 9. 구현 우선순위

### Phase 1. 메인 UX 재정렬

- 첫 진입 시 오늘 날짜 기본 선택
- 메인 입력 카드 우선 배치
- 컴팩트한 캘린더 UI 정리
- 날짜 선택 시 입력 대상 변경

### Phase 2. 세부 관리 구조 정리

- 상세 화면 역할 축소
- 삭제/메모/세부 수정 흐름 정리

### Phase 3. 그래프 및 알림

- 최근 7일/최근 30일 그래프
- 알림 설정 화면
- 아침/저녁 미기록 판정

## 10. 기획상 주의점

- 입력이 관리보다 먼저 눈에 들어와야 한다.
- 캘린더는 예쁘기만 한 컴포넌트가 아니라 상태 확인 도구여야 한다.
- 메인 화면과 상세 화면의 역할이 겹치지 않게 해야 한다.
