# Bplogger 작업 소통 문서

## 1. 목적

이 문서는 현재 프로젝트에 대해 느끼는 문제점, 불만, 개선 요청, 방향 변경 사항을 문서로 정리해서 AI와 지속적으로 소통하기 위한 창구다.

말로 하나씩 지시하지 않아도, 이 문서에 항목을 추가하거나 수정하면 된다.
나는 이 문서를 기준으로 우선순위를 이해하고, 어떤 부분을 어떻게 고쳐야 하는지 판단할 수 있다.

## 2. 사용 방식

이 문서에는 아래 중 필요한 것만 적으면 된다.

- 마음에 안 드는 점
- 왜 마음에 안 드는지
- 원하는 방향
- 절대 원하지 않는 방향
- 급한 순서
- 이번 턴에서 바로 수정했으면 하는 범위

짧게 적어도 되고, 거칠게 적어도 된다.
문장이 완벽할 필요는 없다.

## 3. 내가 이 문서를 읽을 때의 기준

이 문서에 적힌 내용은 아래 순서로 해석한다.

1. 현재 무엇이 문제인지
2. 그 문제가 디자인 문제인지, 기능 문제인지, 구조 문제인지
3. 반드시 지켜야 하는 요구인지, 선호 수준인지
4. 지금 바로 수정해야 하는지, 나중에 정리해도 되는지

```md

우선순위: P1
문제:
-

- 
```

## 6. 우선순위 기준

- `P0`: 지금 방향이 잘못돼서 바로 멈추고 수정해야 하는 것
- `P1`: 다음 작업에서 우선 반영해야 하는 것
- `P2`: 개선하면 좋지만 당장 막히지는 않는 것
- `P3`: 아이디어나 장기 개선 항목

## 7. 분류 기준

- `UI`: 색상, 배치, 컴포넌트 모양, 화면 밀도
- `UX`: 흐름, 버튼 위치, 입력 방식, 피드백 방식
- `기능`: 동작 자체가 잘못됐거나 부족한 경우
- `구조`: 코드 구조, 화면 구조, 상태 관리, 설계 방향
- `성능`: 느림, 버벅임, 불필요한 재렌더링, 로딩 문제
- `데이터`: DB 구조, 저장 정책, 검증, 마이그레s이션
- `문서`: README, docs, 정책 문서, 설명 부족

## 8. 예시

```md
## 캘린더 화면이 너무 복잡함

상태: 신규
우선순위: P1
분류: UX

### 현재 문제
- 한 화면에서 너무 많은 정보를 보여줘서 시선이 분산됨
- 날짜를 눌렀을 때 바로 뭘 해야 하는지 직관적이지 않음

### 왜 문제인지
- 기록 확인과 기록 입력의 목적이 섞여 있음

### 원하는 방향
- 캘린더는 확인 중심
- 입력은 더 명확한 카드 또는 별도 섹션으로 분리

### 원하지 않는 방향
- 정보량만 더 늘리는 방식

### 완료 기준
- 처음 진입했을 때 캘린더의 목적과 다음 액션이 바로 이해됨
```

## 9. 권장 운영 방식

- 새로 마음에 안 드는 점이 생기면 새로운 항목으로 추가
- 기존 항목의 방향이 바뀌면 `원하는 방향`만 갱신
- 해결된 항목은 `상태: 완료`로 변경
- 지금 당장 건드리면 안 되는 것은 `상태: 보류`로 표시

## 10. 이 문서로 요청할 수 있는 예

- "현재 구조가 별로다. 화면 축을 다시 잡고 싶다"
- "캘린더 UX가 마음에 안 든다"
- "지금 구현이 문서와 다르다"
- "README나 docs도 마음에 안 든다"
- "지금 코드는 돌아가도 방식이 별로다"
- "이번 턴에서는 UI만 고치고 싶다"

## 11. 실제 작업 요청 문구 예시


또는

```text
communication-bridge.md에 새 항목 추가했으니 그 기준으로 구조 다시 잡아줘
```

## 12. 현재 합의된 방향

- 앱 첫 진입 시 오늘 날짜를 기본 선택한다.
- 메인 화면 입력은 선택 날짜 기준으로 동작한다.
- 메인 화면은 빠른 입력이 우선이다.
- 캘린더는 확인 중심의 컴팩트한 UI를 지향한다.
- 날짜 탭의 기본 동작은 상세 진입이 아니라 입력 대상 날짜 변경이다.
- 상세 화면은 세부 수정과 관리용 보조 화면이다.
