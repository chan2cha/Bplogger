# Bplogger 남은 정책 질문

## 1. 문서 사용 방법

이 문서는 정책 결정을 기록하는 시트다.
현재 답변이 채워진 항목은 다른 문서에 반영 완료 기준으로 `확정` 처리했다.

## 2. 이미 확정된 내용

- 캘린더는 앱내 캘린더로 구현한다.
- OS 캘린더 직접 연동은 현재 범위에 포함하지 않는다.
- 체중은 선택 입력이다.
- 측정시간은 저장 시점의 기기 시각으로 자동 저장한다.
- 메모는 날짜 단위로 저장한다.

## 3. 정책 결정 기록

### 3.1 저장 구조

질문:

- 아침 혈압과 저녁 혈압을 하나의 세트로 저장할 것인가
- 아니면 각각 독립적으로 저장할 것인가

결정 상태:

```text
확정
```

답변:

```text
1세트의 개념은 없다. 아침과 저녁은 따로 저장이며, 월별 캘린더에는 아침/저녁 모두 없는 경우, 아침만 있는 경우, 저녁만 있는 경우, 모두 있는 경우 총 4가지 상태로 관리하여 표시한다.
```

영향 범위:

- 저장 버튼 활성화 조건
- 알림 해제 조건
- 수정 UX
- DB 스키마

---

### 3.2 수정/삭제 허용 범위

질문:

- 사용자가 저장된 기록을 자유롭게 수정할 수 있는가
- 사용자가 저장된 기록을 자유롭게 삭제할 수 있는가
- 메모도 별도 수정/삭제 가능한가

결정 상태:

```text
확정
```

답변:

```text
수정 및 삭제는 저장된 혈압/체중 기록 단위로 가능하며 메모도 별도 수정 및 삭제 가능하다.
```

영향 범위:

- 상세 화면 액션
- DAO 메서드
- 확인 다이얼로그 정책

---

### 3.3 날짜별 입력 허용 범위

질문:

- 메인 캘린더에서 선택한 날짜로 혈압/체중을 신규 저장할 수 있는가
- 기존 기록이 있는 날짜는 어떻게 처리하는가
- 메모는 날짜 제약 없이 저장 가능한가

결정 상태:

```text
확정
```

답변:

```text
혈압 및 체중은 선택한 날짜에 기존 기록이 없으면 신규 추가 가능하고, 기존 기록이 있으면 조회/수정이 가능하다. 메모는 과거/미래/오늘을 구분하지 않고 추가, 수정, 삭제가 가능하다.
```

영향 범위:

- 캘린더 탭 저장 UX
- 데이터 입력 흐름
- 사용자 실수 방지 정책

---

### 3.4 입력값 검증 범위

질문:

- 혈압 허용 최소/최대값은 얼마인가
- 체중 허용 최소/최대값은 얼마인가
- 체중 소수점 자릿수는 어떻게 처리할 것인가
- 비정상 수치 입력 시 어떤 정책을 사용할 것인가

결정 상태:

```text
확정
```

답변:

```text
혈압은 50~200, 체중은 0~100kg, 소수점은 둘째 자리까지 반올림으로 하며 비정상 수치 입력 시 저장 차단 정책을 사용한다.
```

영향 범위:

- UI 검증
- 도메인 검증
- 테스트 케이스

---

### 3.5 알림 정책

질문:

- 아침 알림 시각은 언제인가
- 저녁 알림 시각은 언제인가
- 재알림이 필요한가
- 사용자가 알림을 끌 수 있어야 하는가

결정 상태:

```text
확정
```

답변:

```text
알림 시각과 재알림 여부 및 횟수는 사용자가 앱 내에서 설정 및 관리할 수 있어야 한다.
```

영향 범위:

- WorkManager 또는 AlarmManager 설계
- 설정 화면 필요 여부
- 아침/저녁 미기록 판정 로직

---

### 3.6 그래프 정책

질문:

- 기본 기간은 무엇인가
- 기간 전환은 어떤 기준으로 동작하는가
- 혈압 그래프는 어떻게 표시할 것인가
- 체중 그래프는 어떻게 배치할 것인가

결정 상태:

```text
확정
```

답변:

```text
기본 기간은 최근 7일이고 탭으로 최근 7일/최근 30일을 볼 수 있도록 한다. 혈압은 수축기/이완기 2라인으로 하며 체중 그래프는 따로 하되 같은 화면에서 동시에 보이게 한다.
```

영향 범위:

- 그래프 UI
- 조회 쿼리
- 집계 모델

---

### 3.7 추가 구현 결정

질문:

- 수정 시 측정 시간은 유지할 것인가 갱신할 것인가
- 캘린더 4상태는 어떤 기준으로 표현할 것인가

결정 상태:

```text
확정
```

답변:

```text
수정 시 측정 시간은 유지한다. 캘린더 4상태는 보편적인 규칙으로 기록 없음은 중립색, 아침만 기록은 아침 강조색, 저녁만 기록은 저녁 강조색, 모두 기록은 완료색으로 표시하며 텍스트 또는 접근성 라벨로 함께 구분한다.
```

영향 범위:

- 상세 수정 로직
- DB 업데이트 정책
- 캘린더 UI
- 접근성 라벨
