# Bplogger 현재 문제점 정리

## 1. 현재 코드와 확정 정책의 불일치

현재 코드와 문서 초안 상당수는 `아침+저녁 묶음 세트`, `날짜별 최대 3세트`, `오늘 중심 단순 입력` 전제를 가지고 있다.
하지만 최신 정책은 아래와 같이 달라졌다.

- 아침 혈압과 저녁 혈압은 별도 저장
- 혈압/체중은 기록이 없는 날짜에 신규 저장 가능
- 기록이 있는 날짜는 수정 중심으로 동작
- 메모는 과거/오늘/미래 모두 편집 가능
- 캘린더는 날짜별 4상태를 표시
- 그래프는 기본 7일, 최근 30일 전환
- 수정 시 측정 시간은 유지
- 알림은 사용자 설정 기반

즉 지금의 문제는 기능 누락 이전에 제품 모델이 바뀌었는데 문서와 구현이 그 변화를 아직 반영하지 못하고 있다는 점이다.

## 2. 문서 기준으로 아직 남아 있는 쟁점

### 2.1 수정/삭제 대상 명칭 정리 필요

- `open-questions.md`에는 과거 표현으로 `세트 단위`가 남아 있었다.
- 현재 문서에서는 이를 `혈압/체중 기록 단위`로 재정리했다.
- 실제 구현에서도 `아침 혈압`, `저녁 혈압`, `체중`, `메모`를 각각 독립 수정/삭제 대상으로 명확히 유지해야 한다.

## 3. 현재 구현의 구조적 문제

### 3.1 단일 화면 구조

- 현재 화면은 [BloodPressureScreen.kt](/Users/chan/workspace/projects/Bplogger/app/src/main/java/com/example/bplogger/ui/BloodPressureScreen.kt) 하나다.
- 월별 캘린더, 일별 상세, 그래프, 알림 설정을 수용할 구조가 없다.

### 3.2 ViewModel 생성 방식

- 파일: [MainActivity.kt](/Users/chan/workspace/projects/Bplogger/app/src/main/java/com/example/bplogger/MainActivity.kt)
- 현재 `BpViewModel`을 Activity에서 직접 생성한다.
- 화면과 상태가 늘어나면 생명주기 관리와 테스트 구성이 취약해진다.

### 3.3 날짜 정책 반영 구조 부재

- 현재 구조에는 `기록 없으면 추가`, `기록 있으면 수정`, `메모는 미래 날짜 허용` 같은 정책 분기가 없다.
- UI와 도메인 계층 모두에 날짜 정책을 반영해야 한다.

## 4. 데이터 모델 문제

### 4.1 슬롯 중심 스키마

- 현재 [BpRecord.kt](/Users/chan/workspace/projects/Bplogger/app/src/main/java/com/example/bplogger/data/BpRecord.kt)는 슬롯 기반 혈압 모델이다.
- 최신 정책의 날짜 단위 건강 기록, 체중, 날짜 메모 분리 구조와 맞지 않는다.

### 4.2 날짜 상태 계산 모델 부재

- 월력에서 필요한 4상태를 바로 계산할 모델이 없다.
- 날짜 단위 조회 모델과 요약 쿼리가 추가되어야 한다.

### 4.3 측정 시간 유지 정책 미반영

- 현재 구조는 수정 시 각 항목의 측정 시간을 유지하는 정책을 직접 표현하지 못한다.
- update 경로에서 시간 필드를 보호하는 로직이 필요하다.

## 5. 기능 문제

### 5.1 오늘 고정 조회

- 파일: [BpViewModel.kt](/Users/chan/workspace/projects/Bplogger/app/src/main/java/com/example/bplogger/ui/BpViewModel.kt)
- 현재는 사실상 오늘 기록만 다룬다.
- 월별 탐색, 날짜별 신규 추가, 과거 수정, 미래 메모 입력에 모두 맞지 않는다.

### 5.2 입력 검증 부족

- 현재는 숫자 여부 수준의 검증만 있다.
- 최신 정책에서 요구하는 혈압 50~200, 체중 0~100, 소수점 반올림, 저장 차단을 모두 지원하지 않는다.

### 5.3 그래프와 캘린더 기능 부재

- 월별 캘린더 UI가 없다.
- 날짜별 4상태 표현이 없다.
- 최근 7일/최근 30일 그래프 전환도 없다.

### 5.4 메모 기능 부재

- 미래 날짜까지 포함하는 날짜 메모 편집 흐름이 없다.

### 5.5 알림 기능 부재

- 사용자 설정 화면이 없다.
- 시간, 재알림, 횟수 설정이 없다.
- 날짜 변경 시 상태 초기화 로직도 없다.

## 6. 데이터 안정성 문제

### 6.1 파괴적 마이그레이션

- 파일: [MainActivity.kt](/Users/chan/workspace/projects/Bplogger/app/src/main/java/com/example/bplogger/MainActivity.kt)
- `fallbackToDestructiveMigration()` 사용 중이다.
- 데이터 구조 변경 폭이 커서 실제 기록 손실 위험이 높다.

### 6.2 테스트 부재

- 새 정책은 날짜 규칙, 상태 계산, 알림 조건이 많아 테스트 없이 진행하기 어렵다.

최소 필요 테스트:

- 기록 없음 날짜 추가 허용 정책
- 기존 기록 날짜 수정 정책
- 미래 날짜 메모 저장 정책
- 날짜별 4상태 계산
- 혈압/체중 입력 검증
- 그래프 기간별 조회
- 수정 시 측정 시간 유지 정책
- 알림 설정 및 발송 조건

## 7. 우선순위

### 높은 우선순위

- 데이터 모델 재정의
- 날짜 정책 반영
- 캘린더 4상태 계산
- 입력 검증
- 알림 설정 구조

### 중간 우선순위

- 그래프 시각화
- 메모 편집 UX
- 마이그레이션 전략

### 낮은 우선순위

- 서버 연동
- 동기화
- 외부 캘린더 연계
