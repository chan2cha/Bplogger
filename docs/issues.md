# Bplogger 현재 문제점 정리

## 1. 현재 코드와 확정 정책의 불일치

현재 코드와 일부 초기 문서는 `탐색 중심`과 `상세 화면 중심 입력`에 더 가깝다.
하지만 최신 정책은 아래와 같다.

- 앱 첫 진입 시 오늘 날짜 기본 선택
- 메인 화면에서 선택 날짜 기준 빠른 입력
- 캘린더는 확인 중심의 컴팩트한 UI
- 상세 화면은 세부 관리용 보조 흐름

즉 지금의 핵심 문제는 기능 누락보다도 메인 화면의 우선순위가 제품 방향과 맞지 않는다는 점이다.

## 2. 현재 구현의 구조적 문제

### 2.1 메인 우선순위 역전

- 현재 구현은 입력보다 캘린더 탐색과 상세 진입이 먼저 눈에 들어온다.
- 최신 방향은 첫 화면에서 빠른 입력이 우선이어야 한다.

### 2.2 단일 화면 과밀

- 현재 화면은 [BloodPressureScreen.kt](/Users/chan/workspace/projects/Bplogger/app/src/main/java/com/example/bplogger/ui/BloodPressureScreen.kt) 하나에 많은 역할이 섞여 있다.
- 월별 캘린더, 빠른 입력, 일별 상세, 그래프, 알림 설정을 균형 있게 수용하기 어렵다.

### 2.3 날짜 정책 반영 구조 부족

- 첫 진입 오늘 날짜 선택
- 날짜 탭 시 메인 입력 대상 변경
- 상세는 보조 진입

위 정책이 UI 구조에 자연스럽게 반영되지 않았다.

## 3. 기능 문제

### 3.1 캘린더 UX

- 캘린더가 컴팩트한 확인용 컴포넌트로 정리되지 않았다.
- 익숙한 월력보다 개별 버튼 나열처럼 보일 위험이 있다.

### 3.2 입력 UX

- 메인 화면에서 빠른 입력이 가장 먼저 인식되지 않는다.
- 상세 화면으로 의존하는 흐름이 남아 있으면 제품 방향과 충돌한다.

### 3.3 검증 및 저장 정책

- 혈압/체중 범위 검증
- 측정 시간 유지 정책
- 날짜별 추가/수정 분기

이 정책은 유지되어야 하며 UI 개편 과정에서도 훼손되면 안 된다.

## 4. 데이터 안정성 문제

- `fallbackToDestructiveMigration()` 사용 중이라 스키마 변경 시 데이터 손실 위험이 있다.
- UI 개편과 별개로 마이그레이션 전략이 필요하다.

## 5. 우선순위

### 높은 우선순위

- 메인 입력 중심 UX 재구성
- 첫 진입 오늘 날짜 기본 선택
- 컴팩트 캘린더 구조 정리
- 메인/상세 역할 분리

### 중간 우선순위

- 그래프 시각화 개선
- 메모 편집 UX
- 마이그레이션 전략
