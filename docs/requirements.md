# Pulse Log 요구사항

## 1. 문서 목적

이 문서는 현재 구현과 확정된 정책을 기준으로 제품 요구사항을 다시 정리한 기준 문서다.

## 2. 제품 개요

- 제품명: Pulse Log
- 플랫폼: Android
- 목적: 사용자가 혈압, 체중, 날짜 메모를 빠르게 기록하고 캘린더와 그래프로 확인할 수 있게 한다.
- 저장 방식: 로컬 저장 기반 단일 사용자 앱

## 3. 핵심 정책

- 앱 첫 진입 시 오늘 날짜를 기본 선택한다.
- 메인 입력은 선택 날짜 기준으로 동작한다.
- 첫 화면의 기본 탭은 캘린더 탭이다.
- 캘린더는 확인 중심의 컴팩트한 월력 UI여야 한다.
- 날짜 탭의 기본 동작은 상세 진입이 아니라 입력 대상 날짜 변경이다.
- 상세 화면은 세부 수정과 관리용 보조 화면이어야 한다.
- 아침 혈압과 저녁 혈압은 각각 독립적으로 저장한다.
- 혈압과 체중은 선택한 날짜에 기존 기록이 없으면 신규 저장 가능하다.
- 혈압과 체중은 선택한 날짜에 기존 기록이 있으면 수정 가능하다.
- 메모는 오늘, 과거, 미래 날짜 모두 추가/수정/삭제 가능하다.
- 체중은 선택 입력이다.
- 측정 시간은 저장 시점의 기기 시각으로 자동 저장한다.
- 수정 시 측정 시간은 유지한다.
- 혈압 허용 범위는 50~200이다.
- 체중 허용 범위는 0~100kg이다.
- 체중은 소수점 둘째 자리까지 반올림 처리한다.
- 비정상 수치 입력 시 저장 차단 정책을 사용한다.
- 그래프 기본 기간은 최근 7일이다.
- 그래프는 최근 7일/최근 30일 전환을 지원해야 한다.
- 혈압 그래프는 수축기/이완기 2라인으로 표시한다.
- 체중 그래프는 분리된 그래프로 표시하되 같은 화면에서 함께 보여준다.
- 알림 시각, 재알림 여부, 재알림 횟수는 사용자가 설정할 수 있어야 한다.

## 4. 캘린더 요구사항

- 월별 캘린더는 날짜별로 다음 4가지 상태를 구분해 표시해야 한다.
  - 아침/저녁 모두 없음
  - 아침만 있음
  - 저녁만 있음
  - 아침/저녁 모두 있음
- 상태는 색상과 접근성 라벨을 함께 사용해야 한다.
- 메모가 있는 날짜는 별표 또는 동등한 보조 마커를 함께 보여야 한다.
- 선택 날짜는 다른 날짜보다 명확히 구분되어야 한다.
- 오늘 날짜는 선택 날짜와 별개로 구분 가능해야 한다.
- 선택 날짜 요약 영역에는 날짜와 메모 요약이 보여야 한다.

## 5. 메인 입력 요구사항

- 메인 화면에서 선택 날짜 기준으로 혈압과 체중을 바로 입력하거나 수정할 수 있어야 한다.
- 아침 혈압과 저녁 혈압은 각각 수축기/이완기 2필드로 입력해야 한다.
- 체중은 별도 단일 입력 필드로 입력해야 한다.
- 저장 버튼은 각 항목별로 독립 제공해야 한다.
- 빠른 입력에서는 현재 저장값을 별도 텍스트로 반복 노출하지 않고 입력 필드 자체로 확인 가능해야 한다.
- 저장 버튼을 누르면 키보드가 내려가야 한다.
- 저장 전과 저장 직후 버튼 상태 차이가 시각적으로 드러나야 한다.

## 6. 상세 화면 요구사항

- 상세 화면은 주 입력 화면이 아니라 세부 관리 화면이어야 한다.
- 일별 상세 화면에서는 선택 날짜의 혈압, 체중, 메모를 확인하고 관리할 수 있어야 한다.
- 저장된 혈압 기록은 수정 및 삭제할 수 있어야 한다.
- 저장된 체중 기록은 수정 및 삭제할 수 있어야 한다.
- 날짜 메모는 혈압/체중과 별도로 수정 및 삭제할 수 있어야 한다.
- 측정 시간은 상세 화면에서 확인 가능해야 한다.

## 7. 그래프 요구사항

- 기본 표시 기간은 최근 7일이어야 한다.
- 사용자는 최근 7일/최근 30일 전환 UI를 사용할 수 있어야 한다.
- 그래프 범위는 최근 기준 이동 구간으로 계산해야 한다.
- 혈압 그래프는 수축기/이완기 2라인으로 표시해야 한다.
- 체중 그래프는 별도 카드 또는 별도 영역으로 표시하되 같은 화면에 함께 있어야 한다.
- 데이터가 없을 경우 비어 있는 상태 메시지를 제공해야 한다.

## 8. 알림 설정 요구사항

- 아침 알림과 저녁 알림은 독립적으로 on/off 가능해야 한다.
- 아침 시간, 저녁 시간, 재알림 여부, 재알림 횟수를 저장할 수 있어야 한다.
- 설정 화면은 빠른 입력과 동일한 디자인 톤을 유지해야 한다.
- 현재 단계에서는 설정 저장 UI와 로컬 저장이 우선이다.

## 9. 피드백 및 시스템 동작 요구사항

- 저장/수정/삭제 후 결과 메시지는 스낵바로 노출해야 한다.
- 화면 바깥을 터치하면 키보드가 내려가야 한다.
- 키보드가 올라올 때 화면 이동은 가능한 한 부드럽고 자연스러워야 한다.
- 저장 후 캘린더와 그래프 반영은 즉시 이루어져야 한다.

## 10. 데이터 모델 요구사항

- 하루 기록은 날짜 단위로 관리되어야 한다.
- 하루 기록 안에는 아침 혈압, 저녁 혈압, 체중이 각각 독립적으로 존재할 수 있어야 한다.
- 아침 혈압과 저녁 혈압은 각각 저장 여부와 측정 시간이 분리되어야 한다.
- 체중은 nullable이어야 한다.
- 날짜 메모는 하루 기록과 별도로 저장되어야 한다.

## 11. 비기능 요구사항

- 앱 실행 후 바로 오늘 기록 상태와 입력 액션이 이해되어야 한다.
- 신규 입력과 수정 흐름은 메인 화면에서 명확히 구분되어야 한다.
- 네트워크 없이도 모든 핵심 기능을 사용할 수 있어야 한다.
- 코드 구조는 캘린더, 빠른 입력, 그래프, 설정, 상세 화면 단위로 분리되어야 한다.

## 12. 추가 보완 필요 사항

- 알림 시간 형식 검증과 입력 마스킹 보완
- 실제 알림 스케줄링 구현
- DB 마이그레이션 전략 수립
- 상세 화면 입력 스타일 추가 통일
- 접근성 문구와 테스트 케이스 강화
