# Bplogger 요구사항 정리본

## 1. 문서 목적

이 문서는 `open-questions.md`에서 확정된 정책을 반영해 현재 제품 요구사항을 정리한 기준 문서다.
이전 초안의 `세트` 중심 표현은 제거하고 실제 구현 기준으로 다시 정리한다.

## 2. 제품 개요

- 제품명: Bplogger
- 플랫폼: Android
- 목적: 사용자가 아침 혈압, 저녁 혈압, 체중, 날짜 메모를 기록하고 캘린더와 그래프로 확인할 수 있도록 한다.
- 저장 방식: 로컬 저장 기반 단일 사용자 앱

## 3. 핵심 정책

- 캘린더는 앱 내부 캘린더로 구현한다.
- OS 캘린더 직접 연동은 현재 범위에 포함하지 않는다.
- 아침 혈압과 저녁 혈압은 묶음 세트가 아니라 각각 별도로 저장한다.
- 혈압과 체중은 선택한 날짜에 기존 기록이 없으면 신규 저장 가능하다.
- 혈압과 체중은 선택한 날짜에 기존 기록이 있으면 조회와 수정이 가능하다.
- 메모는 오늘, 과거, 미래 날짜 모두 추가/수정/삭제 가능하다.
- 체중은 선택 입력이다.
- 측정 시간은 저장 시점의 기기 시각으로 자동 저장한다.
- 수정 시 측정 시간은 유지한다.
- 혈압 허용 범위는 50~200이다.
- 체중 허용 범위는 0~100kg이다.
- 체중은 소수점 둘째 자리까지 반올림 처리한다.
- 비정상 수치 입력 시 저장 차단 정책을 사용한다.
- 알림 시각, 재알림 여부, 재알림 횟수는 사용자가 앱 내에서 설정할 수 있어야 한다.
- 그래프 기본 기간은 최근 7일이다.
- 그래프는 최근 7일/최근 30일 전환을 지원해야 한다.
- 혈압 그래프는 수축기/이완기 2라인으로 표시한다.
- 체중 그래프는 분리된 그래프로 표시하되 같은 화면에서 함께 보여준다.
- 월별 캘린더는 날짜별로 다음 4가지 상태를 구분해 표시해야 한다.
  - 아침/저녁 모두 없음
  - 아침만 있음
  - 저녁만 있음
  - 아침/저녁 모두 있음
- 캘린더 4상태는 보편적인 색상 규칙과 접근성 라벨을 함께 사용해야 한다.
  - 기록 없음: 중립색
  - 아침만 기록: 아침 강조색
  - 저녁만 기록: 저녁 강조색
  - 모두 기록: 완료색

## 4. 사용자 문제

- 사용자는 날짜별로 아침 혈압과 저녁 혈압 기록 여부를 빠르게 확인하고 싶다.
- 사용자는 선택한 날짜에 혈압과 체중을 추가하거나 수정하고 싶다.
- 사용자는 과거 기록을 캘린더와 그래프로 확인하고 싶다.
- 사용자는 날짜 메모를 자유롭게 관리하고 싶다.

## 5. 핵심 사용자

- 혈압과 체중을 일상적으로 측정하는 개인 사용자
- 복잡한 가입 없이 기기 안에서 바로 기록하고 싶은 사용자
- 아침/저녁 누락 여부를 달력에서 빠르게 확인하고 싶은 사용자

## 6. 기능 요구사항

### 6.1 혈압 입력

- 사용자는 아침 수축기/이완기 혈압을 저장할 수 있어야 한다.
- 사용자는 저녁 수축기/이완기 혈압을 저장할 수 있어야 한다.
- 아침 혈압과 저녁 혈압은 서로 독립적으로 저장할 수 있어야 한다.
- 혈압은 선택한 날짜에 기록이 없으면 신규 저장 가능해야 한다.
- 혈압은 선택한 날짜에 기록이 있으면 조회 및 수정 가능해야 한다.

### 6.2 체중 입력

- 사용자는 체중을 선택적으로 저장할 수 있어야 한다.
- 체중은 소수점 둘째 자리까지 반올림해 저장해야 한다.
- 체중은 선택한 날짜에 기록이 없으면 신규 저장 가능해야 한다.
- 체중은 선택한 날짜에 기록이 있으면 조회 및 수정 가능해야 한다.

### 6.3 입력 검증

- 혈압은 50 이상 200 이하만 허용해야 한다.
- 체중은 0 이상 100 이하 범위만 허용해야 한다.
- 허용 범위를 벗어난 값은 저장을 차단해야 한다.
- 유효하지 않은 값은 UI와 도메인 계층 모두에서 검증해야 한다.

### 6.4 수정 및 삭제

- 저장된 혈압 기록은 수정 및 삭제할 수 있어야 한다.
- 저장된 체중 기록은 수정 및 삭제할 수 있어야 한다.
- 날짜 메모는 혈압/체중과 별도로 수정 및 삭제할 수 있어야 한다.
- 수정 시 기존 날짜 상태, 그래프 데이터, 알림 상태가 함께 갱신되어야 한다.
- 혈압 또는 체중 수정 시 기존 측정 시간은 유지되어야 한다.

### 6.5 캘린더

- 첫 화면은 월별 캘린더여야 한다.
- 캘린더는 연도별/월별/일별 탐색 흐름을 지원해야 한다.
- 월별 캘린더는 날짜별 아침/저녁 기록 상태를 직관적으로 보여줘야 한다.
- 색상만으로 구분하지 않고 텍스트 또는 접근성 라벨을 함께 제공해야 한다.
- 날짜를 누르면 일별 상세 화면으로 이동해야 한다.
- 일별 상세 화면에서는 선택 날짜의 혈압, 체중, 메모를 확인할 수 있어야 한다.
- 선택한 날짜에 기록이 없으면 `추가`, 있으면 `수정`으로 사용자 액션이 명확해야 한다.

### 6.6 메모

- 메모는 날짜 단위로 저장되어야 한다.
- 각 날짜당 메모는 1건만 존재해야 한다.
- 메모는 과거/오늘/미래 날짜에 대해 추가/수정/삭제할 수 있어야 한다.

### 6.7 그래프

- 메인 화면의 두 번째 탭은 그래프 탭이어야 한다.
- 기본 표시 기간은 최근 7일이어야 한다.
- 사용자는 최근 7일/최근 30일 탭으로 기간을 전환할 수 있어야 한다.
- 그래프 범위는 캘린더 월이 아니라 최근 기준 이동 구간으로 계산해야 한다.
- 혈압 그래프는 수축기/이완기 2라인으로 표시해야 한다.
- 체중 그래프는 별도 카드 또는 별도 영역으로 표시하되 같은 화면에 함께 있어야 한다.

### 6.8 알림

- 아침 기록이 없으면 아침 알림을 보낼 수 있어야 한다.
- 저녁 기록이 없으면 저녁 알림을 보낼 수 있어야 한다.
- 아침 알림과 저녁 알림은 독립적으로 판단되어야 한다.
- 알림 시각, 재알림 여부, 재알림 횟수는 사용자가 설정할 수 있어야 한다.
- 날짜가 바뀌면 새로운 날짜 기준으로 알림 상태를 다시 계산해야 한다.

## 7. 데이터 모델 요구사항

- 하루 기록은 날짜 단위로 관리되어야 한다.
- 하루 기록 안에는 아침 혈압, 저녁 혈압, 체중이 각각 독립적으로 존재할 수 있어야 한다.
- 아침 혈압과 저녁 혈압은 각각 저장 여부와 측정 시간이 분리되어야 한다.
- 체중은 nullable이어야 한다.
- 날짜 메모는 하루 기록과 별도로 저장되어야 한다.

## 8. 비기능 요구사항

### 8.1 사용성

- 사용자는 앱 실행 후 바로 오늘 기록 상태를 이해할 수 있어야 한다.
- 신규 입력과 수정 흐름은 구분이 명확해야 한다.

### 8.2 성능

- 저장 후 캘린더와 그래프 반영은 즉시 이루어져야 한다.
- 네트워크 없이도 모든 핵심 기능을 사용할 수 있어야 한다.

### 8.3 신뢰성

- 앱 재실행 후에도 저장된 기록이 유지되어야 한다.
- 잘못된 입력값은 저장 전에 차단되어야 한다.

### 8.4 확장성

- 향후 맥박, 동기화, 내보내기 같은 기능을 추가할 수 있어야 한다.

## 9. 현재 코드 기준 보완 포인트

- 현재 코드의 `세트` 전제와 오늘 고정 흐름은 새 정책과 맞지 않는다.
- 아침/저녁 독립 저장과 날짜 단위 메모 분리를 반영한 데이터 모델 재설계가 필요하다.
- 캘린더, 그래프, 알림 설정 화면이 새 범위에 포함된다.
