# Pulse Log 요구사항

## 1. 문서 목적

현재 구현과 합의된 방향을 기준으로 제품 요구사항을 정리한다.

## 2. 제품 개요

- 제품명: Pulse Log
- 플랫폼: Android
- 목적: 사용자가 날짜별 혈압과 체중을 빠르게 기록하고 캘린더와 그래프로 확인할 수 있게 한다.
- 저장 방식: 로컬 저장 기반 단일 사용자 앱

## 3. 핵심 정책

- 앱 첫 진입 시 오늘 날짜를 기본 선택한다.
- 첫 화면의 기본 탭은 입력 탭이다.
- 메인 입력은 선택 날짜 기준으로 동작한다.
- 캘린더 날짜 탭의 기본 동작은 입력 대상 날짜 변경이다.
- 설정은 1차 탭이 아니라 헤더 우측 톱니바퀴 아이콘으로 진입한다.
- 별도 상세 화면은 현재 사용자 흐름에서 제외한다.
- 날짜 메모 기능은 현재 UI에서 사용하지 않는다.
- 그래프에서 날짜를 선택하고 캘린더로 이동하면 해당 날짜가 선택되어야 한다.
- 아침 혈압과 저녁 혈압은 각각 독립적으로 저장한다.
- 혈압과 체중은 선택한 날짜에 기존 기록이 없으면 신규 저장 가능하다.
- 혈압과 체중은 선택한 날짜에 기존 기록이 있으면 수정 가능하다.
- 체중은 선택 입력이다.
- 측정 시간은 저장 시점의 기기 시각으로 자동 저장한다.
- 수정 시 측정 시간은 유지한다.
- 혈압 허용 범위는 50~200이다.
- 체중 허용 범위는 0~100kg이다.
- 체중은 소수점 둘째 자리까지 반올림 처리한다.
- 비정상 수치 입력 시 저장 차단 정책을 사용한다.
- 그래프 기본 기간은 최근 7일이다.
- 그래프는 최근 7일/최근 30일 전환을 지원해야 한다.
- 혈압 그래프는 수축기/이완기 2라인으로 표시한다.
- 체중 그래프는 분리된 그래프로 표시하되 같은 화면에서 함께 보여준다.
- 그래프에서 중간 미기록 날짜를 건너는 연결 구간은 점선으로 표시한다.
- 알림 시각, 재알림 여부, 재알림 횟수는 사용자가 설정할 수 있어야 한다.
- 사용자는 최근 30일 또는 전체 기록을 CSV 또는 PDF 요약본으로 내보낼 수 있어야 한다.

## 4. 입력 요구사항

- 입력 탭은 선택 날짜 기준 빠른 입력을 제공해야 한다.
- 아침 혈압과 저녁 혈압은 각각 수축기/이완기 2필드로 입력해야 한다.
- 체중은 별도 단일 입력 필드로 입력해야 한다.
- 저장 버튼은 각 항목별로 독립 제공해야 한다.
- 저장 버튼을 누르면 키보드가 내려가야 한다.
- 저장 전과 저장 직후 버튼 상태 차이가 시각적으로 드러나야 한다.
- 저장 후 캘린더와 그래프 반영은 즉시 이루어져야 한다.
- 저장된 아침 혈압, 저녁 혈압, 체중은 항목별로 삭제할 수 있어야 한다.
- 삭제는 확인 다이얼로그에서 사용자가 확정한 경우에만 수행해야 한다.

## 5. 캘린더 요구사항

- 월별 캘린더는 날짜별로 다음 4가지 상태를 구분해 표시해야 한다.
  - 아침/저녁 모두 없음
  - 아침만 있음
  - 저녁만 있음
  - 아침/저녁 모두 있음
- 상태는 색상과 접근성 라벨을 함께 사용해야 한다.
- 선택 날짜는 다른 날짜보다 명확히 구분되어야 한다.
- 오늘 날짜는 선택 날짜와 별개로 구분 가능해야 한다.
- 날짜 선택 시 입력 탭과 그래프 흐름에서 공유하는 선택 날짜가 바뀌어야 한다.
- 선택 날짜의 아침 혈압, 저녁 혈압, 체중 요약을 보여야 한다.
- 선택 날짜 요약은 월력 카드 상단에서 바로 변경되어야 한다.
- 선택 날짜 요약에서 입력 탭으로 이동할 수 있어야 한다.

## 6. 그래프 요구사항

- 기본 표시 기간은 최근 7일이어야 한다.
- 사용자는 최근 7일/최근 30일 전환 UI를 사용할 수 있어야 한다.
- 그래프 범위는 최근 기준 이동 구간으로 계산해야 한다.
- 기록이 없는 날짜도 날짜축에는 포함되어야 한다.
- 연속 기록 구간은 실선으로 표시해야 한다.
- 중간 미기록 날짜를 건너는 연결 구간은 점선으로 표시해야 한다.
- 혈압 그래프는 수축기/이완기 2라인으로 표시해야 한다.
- 혈압 그래프에는 수축기 120, 이완기 80 기준선을 표시해야 한다.
- 체중 그래프는 별도 카드 또는 별도 영역으로 표시하되 같은 화면에 함께 있어야 한다.
- 그래프에는 x축/y축 값, 범례, 포인트가 표시되어야 한다.
- 그래프를 탭하면 가장 가까운 날짜 열을 선택해야 한다.
- 선택 날짜 카드에는 날짜, 해당 값, 캘린더 이동 액션이 함께 표시되어야 한다.
- 점선 구간이 있는 그래프에는 점선 의미를 짧게 안내해야 한다.
- 데이터가 없을 경우 비어 있는 상태 메시지를 제공해야 한다.

## 7. 알림 설정 요구사항

- 설정 화면은 헤더 우측 톱니바퀴 아이콘으로 열 수 있어야 한다.
- 아침 알림과 저녁 알림은 독립적으로 on/off 가능해야 한다.
- 아침 시간, 저녁 시간, 재알림 여부, 재알림 횟수를 저장할 수 있어야 한다.
- 설정 화면은 빠른 입력과 동일한 디자인 톤을 유지해야 한다.
- 현재 단계에서는 설정 저장 UI와 로컬 저장이 우선이다.
- 실제 OS 알림 스케줄링은 후속 작업이다.

## 8. 피드백 및 시스템 동작 요구사항

- 저장/수정/삭제 후 결과 메시지는 스낵바로 노출해야 한다.
- CSV/PDF 내보내기는 Android 공유 시트를 통해 이메일, 메신저, 드라이브 앱으로 전달할 수 있어야 한다.
- 화면 바깥을 터치하면 키보드가 내려가야 한다.
- 키보드가 올라올 때 화면 이동은 가능한 한 부드럽고 자연스러워야 한다.
- 그래프에서 캘린더로 이동할 때 선택 날짜가 유지되어야 한다.

## 9. 데이터 모델 요구사항

- 하루 기록은 날짜 단위로 관리되어야 한다.
- 하루 기록 안에는 아침 혈압, 저녁 혈압, 체중이 각각 독립적으로 존재할 수 있어야 한다.
- 아침 혈압과 저녁 혈압은 각각 저장 여부와 측정 시간이 분리되어야 한다.
- 체중은 nullable이어야 한다.
- 날짜 메모 테이블은 현재 UI에서 사용하지 않지만, 기존 DB 스키마와 마이그레이션 리스크 때문에 일단 유지한다.

## 10. 내보내기 요구사항

- CSV는 UTF-8 BOM을 포함해야 한다.
- 빈 측정값은 `0`이 아니라 빈 칸으로 출력해야 한다.
- CSV 컬럼은 날짜, 아침 혈압, 저녁 혈압, 체중, 각 측정 시각, 수정 시각을 포함해야 한다.
- PDF 요약본은 기록 기간, 기록 일수, 아침/저녁 혈압 기록 수, 체중 기록 수, 평균값, 최근 추이 그래프, 최근 기록 표를 포함해야 한다.
- 내보내기 파일은 앱 cache 영역에 임시 생성하고 `FileProvider`로 공유해야 한다.

## 11. 비기능 요구사항

- 앱 실행 후 바로 오늘 기록 상태와 입력 액션이 이해되어야 한다.
- 신규 입력과 수정 흐름은 메인 화면에서 명확히 구분되어야 한다.
- 삭제 같은 위험 동작은 즉시 실행하지 않고 확인 단계를 거쳐야 한다.
- 네트워크 없이도 모든 핵심 기록 기능을 사용할 수 있어야 한다.
- 코드 구조는 입력, 캘린더, 그래프, 설정, 내보내기, 데이터 정책 단위로 분리되어야 한다.

## 12. 추가 보완 필요 사항

- 실제 알림 스케줄링 구현
- PDF 요약본 시각 품질 개선 및 병원 제출 양식 고도화
- Room 마이그레이션 전략 수립
- 설정 시간 입력 UX 개선
- 접근성 문구와 테스트 케이스 강화
- 사용하지 않는 상세/메모 코드의 최종 제거 여부 결정
